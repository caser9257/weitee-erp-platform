## 1. 问题陈述

市场部当前面临以下管理断点：

1. **合同条款没有成为系统输入**：合同中的付款规则、发货条件、开票条件仍以备注形式存在，无法被后续单据消费
2. **发货放行依赖人工判断**：发货是否允许执行，仍依赖人工解释合同和手工核对收款
3. **信息分散**：项目、合同、销售订单、收款、发货、开票信息分散在不同入口
4. **缺少统一视图**：市场部没有一个可以快速判断"卡在哪、下一步谁处理"的统一台账
5. **生命周期状态不清**：项目生命周期状态口径不清，预警和统计难以稳定落地

---

## 2. 解决方案

### 2.1 核心思路

以合同商业条款为约束，以销售订单为执行载体，以实际收款和财务审核为发货放行条件，以项目生命周期台账和预警为管理视图，构建市场销售执行闭环。

### 2.2 主干流程

```
合同 → 订单 → 收款 → 发货 → 出库 → 开票 → 关闭
```

### 2.3 关键能力

| 能力 | 说明 | 所属模块 |
|------|------|----------|
| 合同商业条款结构化 | 合同中的付款规则、发货条件、开票条件成为结构化字段 | CRM 合同 |
| 发货放行控制 | 系统根据合同条款和收款情况自动判断发货是否放行 | ERP 销售 |
| 市场执行台账 | 以项目为主粒度的聚合视图，覆盖合同、订单、收款、发货、开票 | ERP 销售 |
| 项目生命周期追踪 | 定义统一的 7 阶段生命周期，支持阶段流转和时间线记录 | PMO 项目 |

| 生命周期阶段 | 合同→订单→收款→发货→出库→开票→关闭 | 2026-06-03 |
